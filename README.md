# Technical Specification Sheet: Serafina Autonomous 3D Consultant Platform

This document specifies the complete technical architecture, formal component schemas, mathematical projection pipelines, and exact interface layout geometries for the Serafina autonomous 3D digital consultant platform, engineered as a full-stack, decentralized web application combining an Express/Node.js binary asset and API proxy runtime (`server.ts`), in-browser edge neural inference via Hugging Face Transformers ONNX Web Runtime (`@huggingface/transformers`), and real-time WebGL humanoid skeletal animation via Three.js and Pixiv's VRM standard (`@pixiv/three-vrm`): at the network and server boundary, the Express application binds to local port 3000, mounting Vite development middlewares and exposing high-throughput streaming proxy routes at `/api/vrm` (streaming the 117MB VRM 1.0 humanoid avatar with `Access-Control-Allow-Origin: *` and immutable cache-control headers of `public, max-age=604800, immutable`), `/api/animation/idle` (streaming binary Mixamo FBX motion data with identical CORS and immutable caching), `/api/chat` (providing server-side streaming fallback proxies to Google Gemini 2.5 Flash when edge memory or WebGPU hardware acceleration is constrained), and `/api/ollama/ping` (providing health check and model tag enumeration for optional local Ollama instances); the client-side edge neural inference subsystem operates directly within the browser runtime using `@huggingface/transformers` v3, executing pipeline configurations (`text-generation`) with hardware acceleration prioritized for WebGPU and falling back to multi-threaded WebAssembly CPU execution with quantized FP16 and Q4 precision across a tier of embedded language models (SmolLM2-135M-Instruct, SmolLM2-360M-Instruct, Qwen2.5-0.5B-Instruct, Llama-3.2-1B-Instruct, and DeepSeek-R1-Distill-Qwen-1.5B), persisting serialized weights within the browser's Origin Private File System (OPFS) and IndexedDB stores with real-time download telemetry (`downloadProgress`), and streaming output tokens via a custom `TextStreamer` that emits live inference metrics including generation speed (tokens per second), time-to-first-token in milliseconds, total latency, total token volume, and active hardware device type; the primary viewport is governed by a responsive Three.js WebGL canvas utilizing an ACES Filmic tone-mapped renderer (`THREE.ACESFilmicToneMapping`, `SRGBColorSpace`, exposure constant `1.0`, pixel ratio clamped to `Math.min(devicePixelRatio, 2.0)`) set against a pure neutral vertical studio background gradient (`from-[#f8f9fc] via-[#f1f3f9] to-[#e8ebf4]` in light mode and `from-[#0d0f16] via-[#11131c] to-[#171a26]` in dark mode) terminated by a 160-pixel bottom ambient shadow gradient (`h-40 bg-gradient-to-t from-black/[0.03] dark:from-white/[0.015] to-transparent`) and illuminated by a neutral, zero-tint daylight studio lighting rig comprising an ambient light (`0xffffff`, intensity `0.70`), directional key light (`0xffffff`, intensity `0.85` situated at world position `[1.5, 2.5, 2.2]`), directional cool-fill light (`0xf0f4f8`, intensity `0.40` situated at `[-1.5, 1.5, 1.5]`), and directional rim light (`0xffffff`, intensity `0.30` situated at `[0.0, 2.5, -2.0]`), strictly excluding any warm, amber, or yellow point illuminators; the 3D model entity is instantiated by parsing the VRM 1.0 byte array via `GLTFLoader` with `VRMLoaderPlugin`, executing vertex optimization through `VRMUtils.removeUnnecessaryVertices`, skeleton consolidation via `VRMUtils.combineSkeletons`, and coordinate space transformation via `VRMUtils.rotateVRM0`, fixing the root mesh position at world coordinates `[0.0, -0.16, 0.0]` and positioning a 28-degree field-of-view perspective camera (`THREE.PerspectiveCamera(28, aspect, 0.1, 50.0)`) at coordinates `[0.0, 1.15, 1.65]` focused on target vector `[0.0, 1.05, 0.0]` to guarantee natural waist-level framing above the bottom interface layer, while all skinned meshes and child nodes are exhaustively traversed to set `frustumCulled = false` to permanently eliminate culling of the lower torso, skirt, legs, and feet regardless of viewport aspect ratio or camera proximity; continuous bodily posture is driven by fetching the binary Mixamo idle animation (`mixamo_idle.fbx`), retargeting it into a standard VRM humanoid `AnimationClip` using `vrm-mixamo-retarget`, and applying an exact track-filtering step that eliminates all keyframe tracks prefixed with the normalized `head` and `neck` bone identifiers (`clip.tracks.filter(t => !t.name.startsWith(headPrefix) && !t.name.startsWith(neckPrefix))`), binding the filtered clip to a `THREE.AnimationMixer` executed in an infinite `LoopRepeat` cycle so that skeletal movement across the hips, spine, chest, shoulders, arms, hands, legs, and toes proceeds without ever overriding head cursor tracking; dynamic cursor look-at calibration is achieved by sampling the real-time 3D world coordinates of the normalized head bone (`headNode.getWorldPosition()`), adding a vertical translation of `+0.055` meters to align with the inter-ocular eye axis, projecting that 3D coordinate through the active camera matrix via `headWorldPos.project(camera)` into 2D Normalized Device Coordinates (NDC) bounded by `[-1.0, 1.0]`, computing the instantaneous signed 2D offset vector `(deltaX, deltaY)` relative to the mouse cursor's canvas NDC coordinates (`deltaX = mouseNDC.x - headScreenPos.x`, `deltaY = mouseNDC.y - headScreenPos.y`), and smoothly interpolating head rotation (`headNode.rotation.y = lerp(rotation.y, clamp(deltaX * 0.75, -0.85, 0.85) + saccadeOffsetX, delta * 7.5)`, `headNode.rotation.x = lerp(rotation.x, clamp(-deltaY * 0.60, -0.45, 0.45) + saccadeOffsetY, delta * 7.5)`) and neck rotation (`neckNode.rotation.y = lerp(rotation.y, clamp(deltaX * 0.35, -0.40, 0.40), delta * 6.0)`, `neckNode.rotation.x = lerp(rotation.x, clamp(-deltaY * 0.25, -0.25, 0.25), delta * 6.0)`) with randomized eye micro-saccades (`nextSaccadeInterval` between 1.2s and 3.7s) and periodic eyelid blinks driven by a sine half-wave (`Math.sin(blinkProgress * Math.PI)` applied to expression preset `blink` at 7.5 Hz); speech synthesis and lip articulation are managed by a centralized `LipSyncManager` integrated with the browser's Web Speech API, employing a strict prioritized female voice resolution queue (matching 'Bangla', 'Bengali', 'Veena', 'Google বাংলা', 'India' while filtering out male keywords) configured with pitch constant `1.05` and playback rate `1.05`, receiving `SpeechSynthesisUtterance.onboundary` char index notifications to parse instantaneous spoken phonemes into calibrated VRM 1.0 viseme amplitudes (`aa: 0.35`, `oh: 0.32`, `ou: 0.25`, `ih: 0.22`, `ee: 0.25`, and fallback `aa: 0.18`), maintaining an active utterance window timer (`activeUntil = now + 260ms`) and enforcing a zero-quiver deadzone threshold (`viseme < 0.02 -> 0.00`) with a 180ms decay timeout so that punctuation marks, commas, breaths, and pauses immediately collapse lip weights to absolute zero resting stillness, simultaneously analyzing utterance semantics to actuate emotion presets (`happy: 0.55`, `surprised: 0.45`, `sad: 0.40`, `relaxed: 0.35`) in an identical manner for both fresh generated responses and historical message replays;
